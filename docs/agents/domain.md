# Domain docs

This is a single-context repo. Use `GLOSSARY.md` at the repo root
and ADRs in `docs/adr/`.

Before exploring a feature area, read the glossary and any relevant
ADRs that exist. These files are created when terms or decisions are
resolved; their absence needs no setup work.

Use the glossary's terms in issues, tests, and code discussions.
If a proposed change conflicts with an ADR, surface that conflict
before proceeding.
